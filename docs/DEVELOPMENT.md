# Local development

Every command below was run from a fresh clone on 2026-10-19 (macOS, CPython 3.13.13) and
the observed result is noted.

## Requirements

* Python **3.10 or newer**. The Dockerfile uses 3.13. On Python 3.9 the suite fails
  (8 failures in `test_semantic_confirmer.py` / `test_semantic_proposer.py`), so 3.9 is not
  supported.
* `sentry-sdk` from `requirements.txt` is imported unconditionally by `audit_pipeline.py`,
  so `python3 app.py` and `python3 audit_cli.py` fail with `ModuleNotFoundError` until it is
  installed, even though Sentry itself stays off unless `SENTRY_DSN` is set.

## Setup

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt pytest
```

## Tests

```bash
python -m pytest -q
```

Observed at upstream `172d962`: `100 passed, 1 skipped, 1 xfailed`.

* The skip is `test_real_replay_excerpts_exist_in_live_workspace_sources`. It checks the
  Authority Runtime replay excerpts against the author's external workspace and runs only
  when `AUTHORITY_RUNTIME_WORKSPACE_ROOT` points at a directory containing
  `CURRENT_STATE_BOARD.md` and `BRAIN_CURRENT.md`.
* The xfail is `test_detector_does_not_yet_generalize_to_fresh_semantic_contradictions`
  (`tests/test_conflict_detector.py`): a documented limitation of the deterministic
  conflict detector, not a broken test. Do not remove the marker or edit fixtures to make it pass.

Use `python -m pytest` rather than bare `pytest`: the tests import top-level modules
(`path_a_eval_runner`, `agents.*`) and rely on the repository root being on `sys.path`.

### Run the multi-service topology locally

The Cloud Run layout (one web service plus six role services) can be reproduced on one
machine. Observed: same posture and item count as the in-process run.

```bash
port=8901
for role in memory_extractor authority_classifier conflict_detector verification_gate authority_mapper report_writer; do
  AGENT_ROLE=$role PORT=$port python agent_service.py &
  export "$(echo "$role" | tr '[:lower:]' '[:upper:]')_URL=http://127.0.0.1:$port"
  port=$((port + 1))
done
USE_REMOTE_AGENTS=1 PORT=8900 python app.py
```

Each role service answers `GET /health` with `{"ok": true, "agent": "<role>"}`.

## Path A model eval (network, optional)

`path_a_eval_runner.py` calls a live model and is the only research script that does.
It uses Anthropic when `ANTHROPIC_API_KEY` is set (model from `ANTHROPIC_MODEL`) and a local
Ollama server otherwise (`OLLAMA_API_URL`, `OLLAMA_MODEL`). It writes to
`reports/path_a_eval/` by default, which is git-ignored. Its output is not deterministic and
was not re-run for this guide.

## Reproducing recorded artifacts

The runner scripts in the repository root write new timestamped files into
`path_a_eval_artifacts/` (and `authority_runtime_v0_pass_a.py` overwrites its two
fixed-name files). **Do not run them inside your working tree and commit the result.**
Run them in a throwaway copy instead:

```bash
tmp=$(mktemp -d)
git clone -q . "$tmp/repo"
cd "$tmp/repo"
python authority_runtime_v0_pass_a.py
git status --short   # empty: the fixed-name artifacts regenerated byte-identically
```

Observed on 2026-10-19: `Authority Runtime v0 PASS A: 11/11 frozen outcomes matched;
flagship=BLOCK_STALE_ACTION; mutation_authorized=False`, and `git status` was clean.
